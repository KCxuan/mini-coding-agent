# 异步迁移测试

在项目根目录 `D:\Agent` 运行：

```powershell
# 只运行本次新增的异步测试
.\.venv\Scripts\python.exe -X utf8 -B -m unittest tests.test_async_support tests.test_async_mcp tests.test_async_main -v -b

# 连同原有同步、后台命令、Subagent 等测试一起运行
.\.venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests -t . -q -b
```

沿用 Python 自带的 unittest，不新增测试框架。运行环境需要已安装项目的
`requirements-async.txt` 中的依赖。

## 文件怎么读

| 文件 | 主要检查什么 |
| --- | --- |
| `test_async_support.py` | 同步工作在线程里执行；取消后等工作完成；输入不会互相抢占；审批在工具执行前完成；同步和异步 Hook 都能运行 |
| `test_async_mcp.py` | 连接后会话保持打开；同一个 Task 打开和关闭上下文；连接失败、超时和取消后的清理；并发连接复用；动态工具调用 |
| `test_async_main.py` | 响应重试、工具顺序、压缩、后台结果回收、真实 Subagent 线程交接、轮数限制、退出清理和信号处理 |
| `async_helpers.py` | 每个测试使用独立事件循环、临时目录和预先安排好的模型响应 |

建议先读 `test_background_start_happens_only_after_approval`：它先让“审批回答”停住，
检查后台命令尚未启动，再给出“同意”，检查命令只启动一次。这是在检查用户能观察到的行为。

测试中的 `Mock` 用于代替普通函数；`AsyncMock` 用于代替需要 await 的函数。
`asyncio.Event` / `threading.Event` 用来控制任务何时继续，避免凭猜测等待固定时间。
MCP 的短超时测试则有意触发真正的超时分支。

## 验证边界

- 不读取真实密钥，不调用模型 API，不启动 MCP 服务或 Shell 子进程，不等待真人输入。
- 保留真实的线程适配器、MCP 客户端生命周期、工具分发器和主循环函数。
- MCP SDK 的传输/会话边界使用内存替身，因此不是实际 MCP SDK 通信兼容性或外部服务联调证明。
- 主循环函数从当前源文件提取，避免导入入口时构造真实客户端。没有复制另一份主循环，
  但也没有覆盖入口文件的全部顶层初始化。
- 信号测试调用捕获到的处理器，不向测试进程发送真实 Ctrl+C/SIGTERM；实际终端体验仍需手动验证。
- 原有同步测试仍由全量命令执行。

## 回归检查与验证结果

- 续跑确认先 await 输入，再对返回的字符串执行 strip/lower；对应测试覆盖同意、拒绝、无效输入和 EOF。
- 摘要默认输出额度为 25000，请求 timeout 为 1200；`test_compact.py` 检查它们传给模拟客户端的实际值。
- 两个压缩边界测试分别使用 14000、20000 的小窗口，并只在各自测试对象上设置 2000 的摘要额度，
  以验证模型压缩路径和失败后保留原历史。其他测试继续使用业务默认配置。
- 2026-10-01 全量离线回归：167 个测试全部通过。新增的三个异步测试文件包含 45 个测试，
  另新增一个摘要默认参数测试；输入变体不重复计数。

真实联调使用独立工作目录、合成文件和配置的模型服务，验证了文件工具、后台命令、Subagent
交接、fetch MCP 的两次调用、显式压缩、压缩后继续执行，以及输入 exit 后正常清理（退出码 0）。
本次真实场景没有生成新记忆，不能宣称记忆写入/召回/合并已验证；真实取消、拒绝审批、断网及
HTTP MCP 也未覆盖。模型额外执行了一次场景未要求的 echo done，说明程序正常结束不代表模型完全遵循任务约束。
真实联调日志和本地配置不随仓库发布。
