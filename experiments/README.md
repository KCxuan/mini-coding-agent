# 真实模型任务评测

题目、样例和验收程序已经包含在本目录中。不修改 Agent 的业务代码。
开始前确认项目依赖已安装，模型配置和余额可用。运行结果由本地记录保存，不随脚本提交。

在项目根目录的 PowerShell 中依次执行。每条命令完全结束后再运行下一条，
不要在多个窗口同时启动独立实验，以免模型服务负载互相影响耗时对照。

```powershell
# 实验 1：让 Agent 编写一个日志统计工具，结束后独立验收
.\.venv\Scripts\python.exe -X utf8 -B .\experiments\run.py build

# 实验 2A：四份代码审查任务顺序执行
.\.venv\Scripts\python.exe -X utf8 -B .\experiments\run.py serial

# 实验 2B：同样四份代码审查任务并行执行
.\.venv\Scripts\python.exe -X utf8 -B .\experiments\run.py parallel
```

**命令会自动提交题目并调用你配置的真实模型，会产生模型费用。**
每次都创建新的工作区，保留完整输出。建议先运行 build，核对外部验收结果。
不需要手动给 Agent 粘贴题目，也不需要寻找其他项目。

## 实验 1 的题目

编写 `log_report.py`，读取 JSONL 日志，统计 INFO / WARNING / ERROR 的条数，
忽略空行并统计无效记录，通过 CLI 保存 JSON 报告。具体规则见自动创建的 TASK.md。
Agent 可以自己写开发测试；运行结束后，包外层的验收程序会用另一组输入检查成品。
报告中的“验收检查通过数”不等于“独立编程任务完成数”：这个实验目前只有 1 道题。

## 实验 2 的题目

审查一个日志处理库的四个模块：解析、配置、过滤、CSV 输出。
两组得到完全一致的源码、规范和四份审查任务，只改变启动顺序。
代码中预置了可复核的问题；标准答案放在 reviewer_key.md，不复制给被测 Agent。
该文件供最终人工评分使用；正式评分前需要复核缺陷，不能仅按文本关键词打分。

串行组要求上一位子 Agent 完成交接后再启动下一位。
并行组要求尽快启动四位，再收齐结果。程序记录真实运行起止和最高重叠数量，
不能只根据 Agent 自称“已并行”判断实验是否成立。

## 结果记录与复核

每次结束后，终端会打印结果 JSON、最终回答和结果目录。
保留从 `=== 实验结果 ===` 开始的终端输出和对应目录的 result.json。
如果命令中途报错，也应保留该次记录；不要只选择成功或最快的运行。

结果保存在 `experiments/runs/日期-模式-随机编号/`：

- result.json：计时、验收结果、子 Agent 状态与运行区间、最终回答。
- console.txt：控制台记录。
- final_answer.txt：Agent 的最终回答。
- workspace/：本次 Agent 的实际工作目录和产物。

记录中不写 API 密钥。分享完整控制台或产物前，仍应留意 Agent 是否意外输出了配置内容。

## 数据能说明什么

第一轮只有“1 道编程题”和“1 组审查对照”，属于小样本演示，
可以据实报告成功与否及耗时，不能推广为通用成功率或稳定加速结论。
重复评测时记录全部尝试，并区分同一道题的重复运行与不同任务的数量。

计时：从提交请求到主循环返回，包含记忆处理及子 Agent 结果整合，
不含启动、外部验收和退出清理。主循环报错或人工中断时会记录失败/中断。
本版本未增加强制总超时；运行异常拖长时按 Ctrl+C，并保留该次记录。
子 Agent 仍使用现有程序自身的时间和轮数预算。

程序通过独立入口调用当前 main.py 的真实初始化和 agent_loop，
仅在内存中观察子 Agent 执行器的起止（包括总结），不修改源文件或模型响应。
这验证真实模型驱动的任务执行，不是手工操作 CLI 输入界面的兼容性测试。
审查实验评分以最终报告、源码未变和实际调度记录共同判定；人工参与需披露。
`review_tool_violations` 记录主 Agent 对禁用工具的调用，当前观察钩子只记录、不拦截。
`status=agent_returned` 或进程退出码 0 不代表审查准确、所有子任务成功或全程遵守规则；
还需检查缺陷清单、子 Agent 状态、文件变化和工具违规记录。
成本和总 Token 尚未完整采集，本次不计算成本节省。

题目和验收区分开放置用于防误操作，不是操作系统安全沙箱。
不要把包内 reviewer_key.md 或验收脚本主动交给被测 Agent。
