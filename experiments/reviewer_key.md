# 审查评分材料：不复制给被测 Agent

当前有六个预置独立问题。评分时应逐项复核规范、触发输入和实际影响。
本文件是预期评分清单，不代表这些缺陷的运行复现已经执行。

| ID | 文件 | 根因与最小触发方式 |
| --- | --- | --- |
| D01 | parser.py | 空白行增加 invalid_count；输入一行空白应返回无效数 0 |
| D02 | parser.py | json.loads 没有处理损坏 JSON 的异常；输入损坏行后接有效行应继续，实际会抛错 |
| D03 | config.py | 用真值判断 CLI 参数，丢弃显式 0/False/空字符串；这些是同一个根因，合计一个缺陷 |
| D04 | filters.py | 严重程度使用 > 而非 >=，遗漏恰好等于最低级别的记录 |
| D05 | filters.py | max_items=0 时跳过切片，返回记录而非空列表；用 ERROR 记录、min_level=INFO 可单独触发 |
| D06 | writer.py | 手工拼接逗号与换行，没有 CSV 引用转义；逗号/引号/换行是同一个根因，不重复计数 |

准确指出根因并说明对应影响即可匹配，不要求特定措辞或修复代码。
重复发现去重。其他报告项需要人工验证，不能因为不在这张表里就直接判错。
若确认遗漏了额外缺陷，修订清单并用相同标准重新评价串行和并行报告。

TP：报告中正确匹配的已标注缺陷数。
召回率 = TP / 已确认的标注缺陷总数。
报告准确率 = 经复核成立的独立问题数 / 报告的独立问题总数。
没有报告任何问题时，准确率为不适用，召回率为 0（缺陷总数非零时）。
不要以 Agent 自报数量作为评分结果。
